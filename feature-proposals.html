4.2 UX

4.4 UX

Mini-diff ancré au finding

Les findings pointent file:line sans contexte visuel.

Dans FindingCard, un toggle « ◇ Voir le diff » (même style que la section Suggestion existante) affiche le hunk autour de la ligne, surlignée. Le diff PR est déjà récupéré côté backend ; on l'expose via GET /api/pr/.../diff et on extrait le hunk avec split_unified_diff().

5.1 Feature

Review incrémentale

Ne re-analyser que les fichiers changés depuis la dernière review.

Quand une review cachée est stale (le head a bougé), un bouton « ⟳ Review des nouveaux changements » calcule le diff reviewed_sha → head (nouvelle méthode VCS get_diff_between_shas via gh api compare), ne revoit que ces fichiers et fusionne : les findings des fichiers inchangés sont conservés.

5.2 Feature

Prompts éditables + restauration

Customiser les prompts IA, garder les défauts de côté.

Onglet Prompts de la modale Settings : édition des prompts review/fix/analyze. Les versions custom sont sauvées à part (.cache/prompts.json) ; les défauts de _prompts.py restent intacts et « ↺ Restaurer défaut » supprime juste l'override. Sauvegarde bloquée si un placeholder requis ({pr_number}, {repo_full_name}) est manquant.

5.7 Feature

File d'attente multi-PR

Lancer des reviews sur plusieurs PR d'un coup.

Mode sélection dans la liste des PR (cases à cocher) + bouton « ⧉ Review N sélectionnées ». Un store reviewQueue orchestre les startReview() existants avec un cap de concurrence et dépile aux transitions done/error. 100% frontend : chaque review reste un SSE indépendant (aucun changement backend).
